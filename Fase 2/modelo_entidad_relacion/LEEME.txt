MODELO ENTIDAD-RELACIÓN DE MYWORKSAPP
=====================================

Qué es
------
El modelo de datos de MyWorksApp: PostgreSQL en Supabase, esquema public,
proyecto wxqrfcqifkfgawrnqmnj. Las figuras y los scripts salen del esquema
real de la base, leído en modo solo lectura (migración 20261117223850,
17-11-2026, hora de Chile).

El catálogo vivo del 23-11-2026 tiene 76 tablas. El archivo que se abre en
MySQL Workbench para explicar el modelo es modelo_er_central_workbench.sql
(12 tablas centrales). Este LEEME y modelo_er_mysql_workbench.sql siguen
siendo el snapshot de 57 tablas. No se borran.

  57 tablas · 458 columnas · 57 claves primarias
  85 claves foráneas (84 entre tablas de public + perfiles.id -> auth.users.id)
  RLS activo en las 57 tablas · sin ENUM (los estados usan CHECK) · una vista
  (encuestas_testing_con_puntaje), que no se dibuja

Cómo leer los diagramas (notación crow's foot)
----------------------------------------------
  PK          clave primaria (subrayada)
  FK          clave foránea física (cursiva)
  FK*         relación lógica sin FOREIGN KEY (línea punteada gris)
  ?           la columna admite NULL
  caja gris   tabla de otro dominio (se muestra solo para la relación)
  pata de gallo = muchos · barra = uno · círculo = opcional
  Ejemplo: perfiles ||──o< trabajos = un perfil tiene 0..N trabajos y cada
  trabajo tiene exactamente un cliente.

Dominios
--------
  01 Usuarios, autenticación y territorio (10): perfiles, codigos_restablecimiento,
     consentimientos_usuario, dispositivos_push, verificacion_eventos, suscripciones,
     bloqueos_usuario, paises, regiones, comunas
  02 Profesionales, servicios y precios (11): trabajadores, trabajador_precios,
     trabajador_servicios, trabajador_servicios_extra, trabajador_horarios,
     trabajador_horas_publicadas, portafolio_trabajador, impulsos,
     categorias_servicio, servicios, configuraciones_servicio
  03 Trabajos, reservas, reprogramación y PIN (11): trabajos, propuestas_cotizacion,
     propuesta_cotizacion_items, acuerdos_trabajo, cancelaciones_trabajo, reprogramaciones_trabajo,
     pines_inicio_trabajo, bloqueos_pin_inicio, intentos_pin_inicio, fotos_trabajo,
     ubicacion_en_vivo
  04 Pagos, escrow, liquidaciones y cuentas bancarias (5): pagos, ordenes_cambio,
     liquidaciones, metodos_pago_oneclick, cuentas_bancarias
  05 Comunicación, notificaciones, disputas y soporte (5): mensajes, notificaciones,
     disputas, disputa_mensajes, tickets_soporte
  06 Calificaciones y ranking (6): calificaciones, calificaciones_cliente,
     senales_resena, eventos_ranking, ranking_aprendizaje, ranking_config
  07 Administración, moderación y auditoría (9): acciones_pendientes, reportes,
     eventos_abuso, registros_error_app, eventos_analitica, banderas_funcionalidad,
     app_config, encuestas_testing, encuesta_testing_respuestas

Relaciones principales
----------------------
  - perfiles 1:1 auth.users. perfiles es el centro del modelo: 34 tablas lo
    referencian (44 FK).
  - trabajadores 1:0..1 perfiles (la PK de trabajadores es id_usuario).
  - trabajos N:1 perfiles dos veces: el cliente (id_usuario, obligatorio) y el
    profesional (id_trabajador, opcional hasta que se asigna).
  - trabajos 1:N pagos, con un solo pago principal activo por índice único
    parcial. pagos 1:0..1 liquidaciones (índice único en id_pago).
  - pagos y ordenes_cambio se referencian mutuamente: la orden genera su pago.
  - paises 1:N regiones 1:N comunas.

Relaciones lógicas (sin FOREIGN KEY física)
-------------------------------------------
  metodos_pago_oneclick.id_trabajo_pendiente -> trabajos.id
  bloqueos_pin_inicio.pin_ok_usuario  -> perfiles.id
  trabajos.(id_trabajador, id_sku_servicio) -> trabajador_precios.(id_usuario, codigo)
  Polimórficas: notificaciones.id_relacionado y acciones_pendientes.id_entidad.

Archivos
--------
  modelo_er.dbml                 Abrir en https://dbdiagram.io (Import > DBML).
  modelo_er_postgres.sql         DDL PostgreSQL: tablas, PK, UNIQUE y FK. Se revisó
                                 con el analizador de PostgreSQL: crea 57 tablas y 84 FK. No
                                 incluye RLS, funciones ni datos. No ejecutarlo
                                 contra producción.
  modelo_er_mysql_workbench.sql  Mismo modelo en MySQL 8 para MySQL Workbench:
                                 File > Import > Reverse Engineer MySQL Create Script.
                                 Los tipos se adaptan (uuid -> CHAR(36), jsonb -> JSON,
                                 timestamptz -> DATETIME(6), text -> VARCHAR/TEXT).
  fuentes/er_*.dot               Fuente Graphviz de cada figura.
  _gen_modelo_er.py              Regenera todo lo anterior.
  validacion_modelo_er.txt       Conteos y chequeos de la última generación.

Cómo regenerar (desde la raíz del repo grupal)
----------------------------------------------
  1. Actualizar el snapshot MyWorksAppProyect/docs/_schema_public.json desde la
     base, en modo solo lectura. Es el mismo snapshot que usa el diccionario.
  2. python3 "Fase 2/modelo_entidad_relacion/_gen_modelo_er.py"   (requiere Graphviz)
  3. python3 MyWorksAppProyect/docs/_gen_diccionario_desde_schema.py
     Incrusta las figuras en DICCIONARIO_BASE_DATOS.md/.docx (sección
     «Modelo entidad-relación»), con la explicación de cada dominio, el flujo de
     pago y escrow y las decisiones de diseño.
  Revisar validacion_modelo_er.txt: debe decir «ninguna» en tablas sin dominio
  y en FK ausentes.
